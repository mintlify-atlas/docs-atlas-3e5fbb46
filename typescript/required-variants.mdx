---
title: Required variants
description: Make specific CVA variant props required using TypeScript utility types.
---

By design, all variant props generated by `cva` are optional. CVA keeps its API small and unopinionated, so it does not provide a built-in mechanism for required variants. You can enforce required variants yourself using standard TypeScript utility types.

## Making a variant required

Use `Omit` to remove the optional variant from `VariantProps`, then use `Required<Pick<…>>` to re-add it as required.

```typescript button.ts
import { cva, type VariantProps } from "class-variance-authority";

export const buttonVariants = cva("…", {
  variants: {
    optional: { a: "…", b: "…" },
    required: { a: "…", b: "…" },
  },
});

export type ButtonVariantProps = VariantProps<typeof buttonVariants>;

export interface ButtonProps
  extends Omit<ButtonVariantProps, "required">,
    Required<Pick<ButtonVariantProps, "required">> {}

export const button = (props: ButtonProps) => buttonVariants(props);

// ❌ TypeScript Error:
// Argument of type "{}" is not assignable to parameter of type "ButtonProps".
//   Property "required" is missing in type "{}" but required in type "ButtonProps".
button({});

// ✅
button({ required: "a" });
```

The `Omit` + `Required<Pick<…>>` pattern works for any number of variants you want to make required. List each variant name in the `Omit` and `Pick` calls.

```typescript
export interface ButtonProps
  extends Omit<ButtonVariantProps, "intent" | "size">,
    Required<Pick<ButtonVariantProps, "intent" | "size">> {}
```

<Note>
  This pattern does not change CVA's runtime behavior. CVA still accepts `undefined` for every variant internally. The requirement is enforced only at the TypeScript level, so callers must provide the value before it reaches the function.
</Note>

## Why variants are optional by default

`cva` leaves all variant props optional so that:

- You can define `defaultVariants` and omit the prop at the call site.
- The library stays small and framework-agnostic — it does not need to understand which variants are semantically required for your component.
- You retain full control over the public interface of each component through TypeScript.

When a variant has no `defaultVariants` entry and is not passed by the caller, CVA produces no output for that variant group. Making the variant required at the TypeScript level is the correct way to prevent this from happening silently.

## Alternative: discriminated unions

For complex components where the required variant determines which other props are valid, a discriminated union gives you more precise control than `Required<Pick<…>>`.

```typescript button.ts
import { cva, type VariantProps } from "class-variance-authority";

const buttonVariants = cva("font-semibold border rounded", {
  variants: {
    intent: {
      primary: ["bg-blue-500", "text-white"],
      destructive: ["bg-red-500", "text-white"],
    },
    size: {
      small: ["text-sm", "py-1", "px-2"],
      medium: ["text-base", "py-2", "px-4"],
    },
  },
});

type ButtonVariantProps = VariantProps<typeof buttonVariants>;

type PrimaryButtonProps = Omit<ButtonVariantProps, "intent"> & {
  intent: "primary";
  label: string;
};

type DestructiveButtonProps = Omit<ButtonVariantProps, "intent"> & {
  intent: "destructive";
  confirmText: string;
};

type ButtonProps = PrimaryButtonProps | DestructiveButtonProps;

const button = (props: ButtonProps) => buttonVariants(props);

// ✅ Primary requires `label`
button({ intent: "primary", label: "Submit" });

// ✅ Destructive requires `confirmText`
button({ intent: "destructive", confirmText: "Delete permanently" });

// ❌ TypeScript Error — `intent` is required
button({ size: "small" });
```

<Tip>
  Use `Required<Pick<…>>` when you only need to mandate that a caller provides a value. Use a discriminated union when the required variant drives the shape of the rest of the props.
</Tip>
