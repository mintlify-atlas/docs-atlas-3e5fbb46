title: Astro
description: Use CVA in Astro components to build type-safe, variant-driven UI with Tailwind CSS.
---

CVA works in Astro's frontmatter script block. Define your variants, extract the props with `VariantProps`, and call the function in the component markup.

## Component example

```astro components/button.astro
---
import type { HTMLAttributes } from "astro/types";
import { cva, type VariantProps } from "class-variance-authority";

const button = cva("button", {
  variants: {
    intent: {
      primary: ["bg-blue-500", "text-white", "border-transparent"],
      secondary: ["bg-white", "text-gray-800", "border-gray-400"],
    },
    size: {
      small: ["text-sm", "py-1", "px-2"],
      medium: ["text-base", "py-2", "px-4"],
    },
    disabled: {
      false: null,
      true: ["opacity-50", "cursor-not-allowed"],
    },
  },
  compoundVariants: [
    {
      intent: "primary",
      disabled: false,
      class: "hover:bg-blue-600",
    },
    {
      intent: "secondary",
      disabled: false,
      class: "hover:bg-gray-100",
    },
    { intent: "primary", size: "medium", class: "uppercase" },
  ],
});

export interface Props
  extends Omit<HTMLAttributes<"button">, "disabled">,
    VariantProps<typeof button> {}

/**
 * For Astro components, set your defaultVariants within Astro.props
 * (which are `undefined` by default) rather than inside `cva`.
 */
const {
  class: className,
  intent = "primary",
  size = "medium",
  disabled = false,
} = Astro.props;
---

<button
  class={button({ intent, size, disabled, className })}
  disabled={disabled}
>
  <slot />
</button>
```

<Note>
  Astro uses `class` as the attribute name, not `className`. CVA accepts both — the example above uses `className` as a local variable to avoid shadowing the reserved word, then passes it into CVA under the `className` key. Both `class` and `className` work in the CVA call itself.
</Note>

## Setting defaults in `Astro.props`

Set your default variant values by destructuring `Astro.props` with default assignments rather than using `cva`'s `defaultVariants` option. Astro props are `undefined` when not passed, so placing the defaults at the destructuring site keeps the component's public API explicit:

```astro
const { intent = "primary", size = "medium", disabled = false } = Astro.props;
```

<Tip>
  You can still use `defaultVariants` in `cva` if you want the defaults to apply when calling the variant function outside a component context, for example in a shared utility file.
</Tip>
