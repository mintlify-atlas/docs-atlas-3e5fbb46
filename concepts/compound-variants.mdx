---
title: Compound variants
description: Apply classes only when a specific combination of variants is active.
---

Compound variants let you apply classes conditionally based on the combination of active variants. A compound variant's classes are added only when **all** of the specified variant conditions match.

## Basic example

Add a `compoundVariants` array to your `cva` config. Each entry is an object that specifies the variant values that must all be active, plus a `class` (or `className`) to apply when they are.

```typescript button.variants.ts
import { cva } from "class-variance-authority";

const button = cva(["font-semibold", "border", "rounded"], {
  variants: {
    intent: {
      primary: ["bg-blue-500", "text-white", "border-transparent"],
      secondary: ["bg-white", "text-gray-800", "border-gray-400"],
    },
    size: {
      small: ["text-sm", "py-1", "px-2"],
      medium: ["text-base", "py-2", "px-4"],
    },
  },
  compoundVariants: [
    {
      intent: "primary",
      size: "medium",
      class: "uppercase",
    },
  ],
});

// Both conditions match → "uppercase" is applied
button({ intent: "primary", size: "medium" });
// => "font-semibold border rounded bg-blue-500 text-white border-transparent text-base py-2 px-4 uppercase"

// Only one condition matches → "uppercase" is NOT applied
button({ intent: "primary", size: "small" });
// => "font-semibold border rounded bg-blue-500 text-white border-transparent text-sm py-1 px-2"
```

## Targeting multiple values for one variant

You can pass an array of values for any variant key in a compound variant entry. The compound variant matches when the active value is any of the values in the array.

```typescript button.variants.ts
import { cva } from "class-variance-authority";

const button = cva(["font-semibold", "border", "rounded"], {
  variants: {
    intent: {
      primary: ["bg-blue-500", "text-white", "border-transparent"],
      secondary: ["bg-white", "text-gray-800", "border-gray-400"],
    },
    size: {
      small: ["text-sm", "py-1", "px-2"],
      medium: ["text-base", "py-2", "px-4"],
    },
  },
  compoundVariants: [
    {
      // Matches intent="primary" OR intent="secondary", as long as size="medium"
      intent: ["primary", "secondary"],
      size: "medium",
      class: "uppercase",
    },
  ],
});

button({ intent: "primary", size: "medium" });
// => "… uppercase"

button({ intent: "secondary", size: "medium" });
// => "… uppercase"

button({ intent: "primary", size: "small" });
// => "…" (no uppercase — size doesn't match)
```

## Boolean variants in compound variants

Compound variants work with boolean variants too. Use the actual boolean value as the key:

```typescript
const button = cva(["font-semibold", "border", "rounded"], {
  variants: {
    intent: {
      primary: ["bg-blue-500", "text-white", "border-transparent"],
      secondary: ["bg-white", "text-gray-800", "border-gray-400"],
    },
    disabled: {
      true: ["opacity-50", "cursor-not-allowed"],
      false: null,
    },
  },
  compoundVariants: [
    {
      intent: "primary",
      disabled: false,
      class: "hover:bg-blue-600",
    },
    {
      intent: "secondary",
      disabled: false,
      class: "hover:bg-gray-100",
    },
  ],
  defaultVariants: {
    intent: "primary",
    disabled: false,
  },
});
```

## `class` vs `className`

Each compound variant entry accepts either `class` or `className` to specify the classes to apply. Both work identically — use whichever feels natural for your framework.

<Tabs>
  <Tab title="class (framework-agnostic)">
    ```typescript
    compoundVariants: [
      {
        intent: "primary",
        size: "medium",
        class: "uppercase",
      },
    ]
    ```
  </Tab>
  <Tab title="className (React)">
    ```typescript
    compoundVariants: [
      {
        intent: "primary",
        size: "medium",
        className: "uppercase",
      },
    ]
    ```
  </Tab>
</Tabs>

<Note>
  You can use `class` and `className` in different entries of the same `compoundVariants` array. They are not exclusive across entries, only within a single entry.
</Note>
